# Versioning

## How it works

The version comes from git, is baked in at build time, and is visible in-game — so a
bug report can name the exact build. No hand-maintained version constants.

## Canonical code

**Write it** — a task stamps `git describe` into a gitignored assets file, and build
tasks depend on it so every bound binary is stamped (`Taskfile.yml`):

```yaml
store-version:
  cmds:
    - git describe --tags > assets/version
```

**Read it** — the file rides the assets package's existing `//go:embed *` and is read
at startup, falling back to `"dev"` when absent (`assets/assets.go`):

```go
var (
    //go:embed *
    assetsFS embed.FS

    Version = "dev"
)

// in MustLoadAssets():
version, err := fs.ReadFile(assetsFS, "version")
if err == nil {
    Version = strings.TrimSpace(string(version))
}
```

**Show it** — `game.NewGame` puts `assets.Version` into the scene context; the main
menu renders `"Version: " + m.context.Version` in small text at the panel's bottom
(`scene/main_menu.go`).

**Server binaries** — no assets package, so inject via the linker instead
(`Dockerfile`; the workflow passes `BUILD_VERSION=$(git rev-parse --short HEAD)`):

```dockerfile
ARG BUILD_VERSION
RUN ... go build -ldflags="-s -w -X main.BuildVersion=${BUILD_VERSION}" -trimpath -o /server ./server
```

## Rules

- Version source is `git describe --tags`; never edit a version string by hand.
- The stamp file is gitignored and regenerated by the build task; the `"dev"` fallback
  keeps an unstamped `go run .` working and honestly labeled.
- Display it in-game (main menu or corner overlay) — a version nobody can see stamps
  nothing.

## Pitfalls

- **`-X main.BuildVersion=...` on a variable that doesn't exist is a silent no-op** —
  the linker doesn't complain. Declare `var BuildVersion = "dev"` in the server's
  `package main` and log it at startup, so a missing stamp shows.
- Every CI workflow that builds needs the stamp step before `go build`, the web one
  included (see [wasm.md](wasm.md)); a forgotten one ships builds that report `dev`.
